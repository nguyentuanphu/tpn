# Numbered builder instructions

Do not jump directly from this concept to many new screens. Each step has a reviewable output and pass condition. If required information is missing, record the exact gap and continue independent work; do not fill it with invented data.

| Step | Inputs → required outputs | Pass condition |
|---|---|---|
| B00 Resume | Repo rules, status, exact CI artifacts → RESUME-STATE.md | Clean understanding of user edits, branch, source and actual failures/retries; no deployment inferred |
| B01 Inventory | All 13 domains and source catalogues → INVENTORY.json/md | Every intended typed item has source and implementation/discovery/dependency status; unknowns explicit |
| B02 Controls | Registry plus real write/read paths → CONTROL-COVERAGE.json/md | Every required control has capability state and evidence; gaps remain blockers |
| B03 Schemas | Existing 279-entry register and current routes → FIELD-CONTRACTS.json/md, SCHEMA-CHANGES.md | Types/units/joins/grants/eligibility/retention/null states defined before collection |
| B04 Home | Real sources and audited denominators → HOME-FIELD-MAP.md and Home implementation | At most three priorities, useful summaries/two principal graphs; coverage/freshness honest |
| B05 People | Authorised installation/profile links → private detail journey | Names remain device-associated; grants/opt-out/no false identity joins verified |
| B06 Item journey | One real content item → ITEM-WORKSPACE.md and complete editor | Source → game entry → website → controls → measurements → work/history explainable |
| B07 Draft/review | Existing publication limitations → actual private draft/review contract | Save draft does not publish; revision conflict/preview/approval/readback tested |
| B08 Broaden coverage | Inventory and control matrix → all-domain workspace coverage | No intended item lost; missing runtime/control remains visible, not green metadata |
| B09 Website/marketing | Existing aggregates and source rules → page alignment and essential funnel | Same source/version/art, observable denominators, unknown attribution explicit |

| B13 Review/package | Current source, tests and visuals → VALIDATION.md, screenshots, STATUS.md, NEXT-CHAT.md | Required checks and EN/VI/device review recorded; public links/downloads verified; owner release decision remains separate |

For each code task: identify source ownership and dependencies, inspect actual consumer, implement a complete vertical slice, run required meaningful checks via tests/suite.mjs and retain exact evidence. No concurrent local suites. If changed-check selection needs full suite, use GitHub per repository rules. Never weaken assertions or silently skip failures. Do not rerun an unchanged suite just for packaging.

## Acceptance gates

1. Inventory completeness and control completeness are independently reviewed.
2. No catalogue entry is labelled playable from metadata alone.
3. Every graph has denominator/source/eligibility/time basis/null/freshness/drilldown contract.
4. Server grants protect private reads/writes regardless of visible navigation.
5. Private drafts, public config, deployed build and device observations remain distinct.
6. Optional off/on paths preserve saves, parent choices and game play; resource measurements meet established budgets.
7. Marketing cannot access child names and cannot infer unavailable identity/attribution.
8. Currency/FX/tax/audit and partial-source financial caveats remain exact.
9. Actual existing Netlify service is verified; no new paid provisioning or production URL copying into preview.
10. Relevant EN/VI, phone/tablet/computer, offline/update/conflict/failure states have evidence; physical-device gaps disclosed.
11. No main merge, deploy, version change, payments or destructive family-data operation without relevant explicit authority.
