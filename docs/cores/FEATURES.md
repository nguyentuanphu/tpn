# Feature list for the Studio Release page (draft, 8 Oct AEST)

Every line becomes a switch in Sparkle Studio → **Ra mắt** (Releases).

## How a switch works (owner's answers, 8 Oct AEST)
- **On or Off**, for everyone at once. There is no test step and no gradual rollout.
- **Defaults:** every feature, old and new, starts **On**. The owner switches off what they want. The "Suggested start" column below is only a suggestion.
- **Days:**
  - **Start in N days**, or at a date and time (AEST): the feature switches on by itself.
  - **On for N days only:** a limited-time feature or event that switches off by itself; what children got from it stays theirs and usable.
  - **"New" badge for N days:** default 7.
- **"New!" moment when a feature goes live:**
  - A MỚI badge.
  - The companion flies over, says what's new and can lead the child to it.
  - A "Có gì mới" card the next time the child starts.
  - A gift the first time the child tries it.
- **Turning a feature off (owner, 8 Oct): it only stops new things; it never takes away or hides what a child already has.**
  - What stops, at the next start or within about 5 minutes while playing: the shop stops selling it, the event stops running, the surprise stops appearing, and children who never tried it no longer see it.
  - What stays, visible and usable: everything the child owns or earned from it (coins, clothes, items, homes and their upgrades, pets, stickers, collectibles, stars, prizes).
  - Games and places already played: children who already played a game or visited a place keep it and can go on using it. It just gets no "new" announcements.
  - Switching it back on brings it back for everyone.
- **Always on:** making a character, saving, Grown-ups, time limits and safety.
- **Instant:** the switches live on the website (Netlify Blobs), so there is no Publish and no deploy. Offline, the game uses the last switches it saw.

Columns below: **Suggested start** = my suggestion only (Live, or Off then drip = hide now and release later as "new"); the real default is On.

## H. Every game switch has a Studio control (r85, owner 18 Oct 2026 AEDT)
Owner: "ensure all function in game should be able to control by studio"; "stories film switch is not available on
studio". Audit on 18 Oct AEDT (`main` r83) of every switch the game reads (`featureOn`, `releaseOn`, `keptOn`, `G.keep`
and each file's own `keep` / `feat`): all but one were already on Studio's Releases page or Sparkle Lab; the story films
(`storyFilms`, js/tales.js and js/howto-player.js) were only on the Defaults page, which waits for Publish. They are now
a card in Releases → The lantern story (live at once, can be scheduled); the Defaults choice stays and says
"Releases wins".

Where each switch is (Releases page groups, `js/content/releases.js`):
- The lantern story (6): the prologue, chapters 1 to 3, Bà Huệ's yard, the story films.
- For little ones (16), Shop and rewards (4), In the valley (8), The living valley (8), Money games (10, one per game),
  Explanations and tips (9), Trials (2: reading games, family devices), Festivals (26: each festival, the hunt, big
  decorations); Sparkle Lab (2: auto play, testers).
- Not a switch but controlled in Studio too: each game's group, Under 5 and Hide (Game → Simple screen), each
  festival's decorations and build-up (Game → Festivals), the device defaults (rest reminder, language, bilingual voice,
  money, captions, calm mode, text size, music: Game → Defaults), and the family's content pages.

The check `studioswitches` (`tests/unit/studioswitches.test.mjs`, part of `unit`, no browser) reads every switch the game
asks for, works out the ones built from a list (`explain_<kind>_note/voice`, `money_<game>`, `story_<chapter>`,
`fest_<festival>`), and fails when one has no card in `RELEASES`, when a switch is read in a way it cannot see, or when the
Defaults page or `content/custom.json` switches something Releases does not have. A new feature therefore needs its
Releases card (id, English, Vietnamese, group, def) before the checks pass.

## Batch calendar (owner, 13 Oct AEDT; replaces the old "Suggested drip calendar")
Owner's decisions (13 Oct AEDT): one batch every Saturday (AEDT), each with a 7-day New badge; features children can
already see are held back and come back as "New!" on their batch day; the owner sets the dates in Studio from a checklist
(`docs/cores/tasks/rollout-checklist.md`, one row per switch: start date and New days).

How it works (js/custom.js, check `rollout`):
- A start date still to come, or Off, hides a feature only from children who never used it. What a child really used
  (rode, tapped, opened, finished a step) is kept on their profile (`profile.tried`) and stays theirs; a save from before
  the rollout counts where it already shows the use. Scenery switches (day plan, animal homes, big decorations) have
  nothing to keep: they simply wait for the date.
- On the start date the feature is on for everyone, with the MỚI badge and the "New in the valley!" card for 7 days.
- Tester devices see each batch 7 days before its start by themselves; the ticked sneak peeks still work too.
- Base game, always on (no batch): the world and its games, the story prologue and chapters 1 and 2, the Simple screen,
  the shop, family missions, bedtime and the other grown-up features, traffic, signposts, the bug fixes. Festivals come by
  their own dates (Festivals page) and are never given a start date on the Releases page.
