## A round, step by step
1. Read `BOARD.md`; merge each ready core branch and each bug robot pull request (`bugfix/*` branches, label
   `fixed-on-branch`: read the fix and its checks first). Every pull request into `main` shows two marks: **Quick checks**
   and **AI review**; fix (or send back) every problem the AI review lists before merging; fix conflicts with the core's owner on the board.
2. Bump r-number in `js/build.js`, `sw.js` VERSION and `studio/version.json`.
3. Record new voices (`tools/make-voice-pack.mts --engine azure`, see Voice & Audio).
4. Run the **full suite** once per release: `cd tests && node suite.mjs` (owner, 13 Oct: 3 checks at a time, the speed checks alone at the
   end, crashed ones once more alone; about an hour; `--all` for no samples). Commit first; afterwards commit the refreshed
   `tests/check-map.json` and `tests/check-times.json`. From a GitHub run (r79, 17 Oct AEDT; cloud chats cannot download its
   artifact): `git fetch origin code-map && git checkout FETCH_HEAD -- tests/check-map.json tests/check-times.json`, then commit.
   Fix or send back every failure. A branch that only adds films or fixes a
   button gets `node suite.mjs --changed` in its own chat; the release still gets one full suite.
5. Update `HANDOFF.md` (round history and checks table) and `docs/ARCHITECTURE.md` §9 if rules changed (`node tools/rules-from-doc.mts`).
6. Packages: the Netlify zip, made by `sh build-netlify.sh` (it builds the TypeScript first, packs the start-up scripts and includes `home/`, the family website, plus voices, photos and sounds; r89: `git archive` of the sources misses the built `.js` files and `home/`). **No local bundle** (owner, 11 Oct: the offline files are on GitHub and the Google Drive mirror). No Studio exe (owner, 23 Oct AEDT: no longer built or published; Studio is online only).
7. Report to the owner: what changed (plain words), how it was tested, the Netlify zip, times in Sydney time (AEDT/AEST).
8. Ask one pop-up question per round: “yes, deploy”. It covers pushing the release branch and merging it into main
   (which makes Netlify publish), for that round only (owner, 10 Oct: Release is the master release; helper chats push
   their own branches without asking).
9. (Done 10 Oct AEST: the Google Drive mirror and the voice relay are set up; no more reminders.)
10. After deploying, check the live deploy in Netlify and say when it went live (AEST).
